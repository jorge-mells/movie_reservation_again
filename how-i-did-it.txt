- design restful api. Think of a flow that makes sense for the app and then design the resources with that flow. Then design the data models using entity relationship modelling. In my experience focus less on performance(database joins are pretty fast, and rather on models that make sense. If a datatype is fairly complex, it should probably be its own model)
- implement services. Ideally one method per resource. Then write tests for the service

- make use of migrations(alembic), settings(pydantic settings), .env, pytest

- a bit about alembic. alembic init sets up the alembic directory and the alembic.ini(configuration); alembic contains a mako script, env.py and versions/. env.py contains functions which are ran upon setting commands to alembic. most of the python configs you want to do happen in env.py. you can also edit the mako script. after setting up, you can change the ini file, but it's more convenient to use config.set_main_option for example in env.py. Then you can also setup env.py for auto generating revisions. A revision is like a commit and consists of instructions(in python) to unify your database with the changes you have made to your models. to autogenerate them, ensure metadata points to something sensible(import models and point metadata to right metadata class; metadata class contains all metadata about tables needed to build them or drop them); then edit the mako file accordingly(importing sqlmodel for example) and then finally generate a revision(don't forget --autogenerate and -m for the revision message); then you can upgrade the database to the new revision(migrating the database).
